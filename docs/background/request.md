# Codex Realtime Board 项目背景

## 背景

`Codex CLI` 已经能够高效完成真实开发工作，但在高强度使用过程中，用户仍然很难直接看到以下 3 类关键信息：

- 当前到底调用了哪些工具、`Skills`、搜索或记忆引用。
- 当前到底处在搜索、计划、执行、编辑还是等待输入阶段。
- 当前上下文预算已经消耗到什么程度，以及什么时候发生了压缩。

这个项目要解决的不是“替代 Codex CLI”，而是给 `Codex CLI` 增加一个按需展开的 companion panel，让用户在不打断主工作流的前提下，获得更高透明度的运行视图。

## 当前路线

当前主线已经明确：

- 保持 `Codex CLI` 作为主工作面。
- 优先消费 `Codex app-server` 的结构化事件，而不是解析终端字符流。
- 在 `Codex CLI` 和 panel 之间保留一层本地 bridge / cache service，用来做会话发现、事件归一化和轻量历史缓存。
- 先把独立 panel 跑通，再逐步封装为 `VS Code` / `Cursor` webview 等宿主形态。

## 非目标

当前阶段不追求：

- 替代原生 `codex` 命令默认工作流。
- 通过终端字符流解析恢复完整产品语义。
- 在 `V1` 中承诺无侵入附着任意裸跑 `codex` 进程。
- 在 `V1` 中做跨会话长期记忆管理器或完整 IDE 集成。
